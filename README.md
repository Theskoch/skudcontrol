# SkudControl

Портал учёта прихода/ухода сотрудников. Тёмная тема, роли ADMIN/USER, таблица сотрудников, дашборд сотрудника с графиком-таймлайном и правкой времени администратором.

## Стек

- Backend: Node.js + Fastify + TypeScript + Prisma + PostgreSQL
- Frontend: React + Vite + TypeScript + Tailwind CSS + TanStack Query
- Docker Compose: `db`, `backend`, `proxy` (nginx, отдаёт фронт и проксирует `/api`)

## Первый запуск

```bash
cp .env.example .env      # и поправьте пароли/секреты
mkdir -p data/postgres data/backups
docker compose up --build
```

Откройте http://localhost:8080 (порт задаётся `WEB_PORT` в `.env`).

При первом запуске backend сам применит миграции (`prisma migrate deploy`), создаст админ-аккаунт из
`SEED_ADMIN_USERNAME`/`SEED_ADMIN_PASSWORD` и импортирует сотрудников из файла отчёта (см. ниже).

## Развёртывание на сервере за Nginx Proxy Manager (HTTPS)

Сам контейнер `proxy` HTTPS не терминирует — это делает внешний реверс-прокси (NPM), а наш
`proxy` слушает обычный HTTP и по умолчанию публикуется **только на loopback хоста**
(`127.0.0.1:${WEB_PORT}`), чтобы порт нельзя было дёрнуть напрямую в обход NPM/HTTPS.

Шаги на сервере:

1. `git clone` репозиторий, `cp .env.example .env`, заполнить реальные секреты (пароли, `JWT_SECRET`,
   `NETWORK_INGEST_TOKEN`, ключи UniFi и т.д.) — сгенерировать длинные случайные значения, не просто "change_me".
2. В `.env` дополнительно выставить:
   ```
   CORS_ORIGIN=https://ваш-домен.example
   COOKIE_SECURE=true
   ```
   `CORS_ORIGIN` — реальный домен с `https://`, без слэша на конце (через запятую можно указать
   несколько, если понадобится). `COOKIE_SECURE=true` — обязательно, иначе браузер не будет
   слать cookie авторизации через HTTPS.
3. `BIND_ADDRESS` можно не трогать (по умолчанию `127.0.0.1`) — раз NPM работает на том же
   сервере. Если NPM стоит на **другой** машине и должен достучаться до этой по сети — поставить
   `BIND_ADDRESS=0.0.0.0` (и озаботиться файрволом, чтобы `WEB_PORT` не смотрел в интернет напрямую).
4. `mkdir -p data/postgres data/backups && docker compose up --build -d`.
5. В Nginx Proxy Manager создать Proxy Host: домен → `http://<ip-сервера-или-имя-хоста>:${WEB_PORT}`
   (тот же `WEB_PORT`, что в `.env`), включить SSL (Let's Encrypt) и Force SSL.

## Импорт отчёта (Report.html)

Папка, в которой backend ищет `Report.html`, задаётся `REPORT_HOST_DIR` в `.env` (по умолчанию —
`./Report`, т.е. папка проекта). Чтобы в будущем читать отчёт из другого места (сетевая папка,
папка другой системы и т.д.), достаточно поменять `REPORT_HOST_DIR` и перезапустить
`docker compose up -d` — код трогать не нужно.

`Report/*.html` — в `.gitignore` (там реальные имена сотрудников клиента, это не должно попадать
в git). На сервере укажите в `REPORT_HOST_DIR` реальный путь к выгрузке — если файла нет вообще,
импорт просто пропускается с предупреждением в логах, ничего не падает.

Файл в этой папке проверяется:
- сразу при старте контейнера (сид),
- вручную — кнопка «Импорт отчёта» в интерфейсе (админ),
- и автоматически раз в час, **в :30 каждого часа** (00:30, 01:30, 02:30, ...), а не ровно в
  начале часа — так и сиды, и ручной импорт, и файл, который клиент перезаписывает по своему
  расписанию, не гоняются друг за другом.

Каждый импорт: добавляет новых сотрудников, обновляет MAC-адрес (берётся из колонки
«Табельный номер» — так исторически сложилось у клиента), помечает пропавших из отчёта на
удаление через 3 месяца, ничего не «додумывает» там, где в отчёте стоит «-».

## Почему база не «внутри» Docker

`docker-compose.yml` монтирует Postgres не именованным volume, а обычной хостовой папкой
`./data/postgres`. Это значит: `docker compose down`, пересборка образов, обновление кода —
ничего из этого не тронет файлы базы, они лежат на диске как обычная директория. `docker compose down -v`
всё равно не нужен и не должен использоваться для обновлений.

Бэкап: `./scripts/backup.sh` делает `pg_dump` в `./data/backups`.

### macOS: если Postgres не стартует из-за прав на `./data/postgres`

```bash
sudo chown -R 999:999 ./data/postgres   # либо chmod -R 777 ./data/postgres для локальной разработки
```

## Разработка без Docker (быстрее итерации)

```bash
# backend
cd backend && npm install
npx prisma migrate dev
npm run seed
npm run dev            # http://localhost:4000

# frontend (в другом терминале)
cd frontend && npm install
npm run dev            # http://localhost:5173, проксирует /api на localhost:4000
```

## Роли

- **ADMIN** — видит всех сотрудников, может добавлять сотрудников и вносить исправления
  в события прихода/ухода (кнопка «Внести изменения» на странице сотрудника). Каждое исправление
  пишется в таблицу аудита `attendance_event_audit`.
- **USER** — тот же обзор (таблица + дашборд), без прав на изменение.

## Пороговые значения (цвет среднего времени)

Хранятся в таблице `app_settings` (можно поменять без редеплоя): зелёный ≥ 7ч, жёлтый 4–7ч,
красный < 4ч, среднее считается по окну 30 дней.
